# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Это **не код-проект**, а контентный репозиторий — два Obsidian-vault'а с учебными материалами по фронтенду. Здесь нет `package.json`, build/test/lint-команд, dev-сервера и CI. Вся работа сводится к чтению и редактированию Markdown-файлов с YAML frontmatter и Obsidian wiki-links (`[[...]]`).

Весь пользовательский контент — на **русском**. Имена папок и файлов — кириллицей (например, `03-CSS-база/`, `10-React-экосистема/`). Сохраняй кириллицу в новых именах, не переводи на латиницу.

## Архитектура двух курсов

Репозиторий содержит **два независимых Obsidian-vault**, открываемые отдельно:

- **`FrontendCourse/`** — базовый курс (с нуля → junior). 15 модулей: `00-Установка/` (VS Code, Node.js, терминал) → `01-Setup/` → … → `14-Деплой-и-финал/`, плюс `MOC/`, `Проекты/` (P1/P2/P3 + `Мини/`), `Приложения/`, `Ресурсы/`, `Шаблоны/`. Уроки `01.4`/`01.5` — отдельный «дизайнерский on-ramp» (Figma → HTML/CSS); если правишь модуль 01, не сломай эту ветку.
- **`FrontendAdvanced/`** — продвинутый курс (middle → senior). 6 треков: `A1-Deep-Frontend/` … `A6-Команда-и-культура/`, плюс собственный `MOC/`. Проекты A-P1…A-P4 — описание в `00-Start-Here.md`, отдельный каталог проектов пока не создан.
- **`PersonalExplanations/`** — личный «черновой» каталог автора (например, `JS/Примитивы и Objects.md`) с заметками вне курсовой структуры. Сюда не применяются правила шаблона урока (6 секций, frontmatter); не трогай эти файлы при массовых рефакторингах курса.

Точка входа каждого vault — `00-Start-Here.md` в его корне. Карты курса и связи между модулями нужно править именно там при добавлении/переименовании модулей.

Базовый и продвинутый курсы — **раздельные vault'а**, не кросс-линкуй между ними wiki-ссылками: `[[...]]` в Obsidian резолвится в пределах одного vault.

## Структура модуля и урока

Каждый модуль (`NN-Название/` в базовом, `AX.Y-Название/` в продвинутом) устроен одинаково:

- `00-Обзор-модуля.md` — чек-лист модуля, ссылка на узел roadmap.sh, список уроков, привязка к MOC.
- Уроки `NN.X-Тема.md` (например, `10.1-React-Router.md`) или `AX.Y.Z-Тема.md`.

**Шаблоны — источник истины для формата:**
- `FrontendCourse/Шаблоны/Шаблон-урока.md` — структура обычного урока.
- `FrontendCourse/Шаблоны/Шаблон-обзора-модуля.md` — структура `00-Обзор-модуля.md`.
- `FrontendCourse/Шаблоны/Шаблон-deep-dive.md` — структура deep-dive (см. ниже).

При создании новых уроков копируй структуру из шаблона. Каждый обычный урок состоит из 6 фиксированных секций именно в этом порядке: **Зачем это нужно → Главное → Пример кода → Частые ошибки → Задания → Что почитать**. Не меняй порядок, не объединяй секции, не добавляй новые верхнеуровневые разделы — Dataview-запросы и единообразие vault'а на это рассчитывают.

Объём «Главного»: ~150–400 слов в базовом курсе, 500–1000 слов в продвинутом. Реалистичные код-примеры, не учебные «foo/bar».

### Второй тип заметки — deep-dive

Помимо обычных уроков есть **второй тип** — `NN.X-Тема-deep.md` рядом с поверхностным `NN.X-Тема.md`. Это дополнительный слой для тем, где базового урока физически не хватает (JS-внутренности, рендер браузера, React-reconciliation, system design, продвинутые алгоритмические темы). Для большинства уроков deep-dive **не нужен**.

Признаки deep-dive:
- Поле `тип: deep-dive` во frontmatter (у обычных уроков поле `тип:` отсутствует — это формальный различитель для будущих Dataview-запросов).
- **Другая структура секций** — НЕ шестёрка обычного урока. Вместо неё: **Модель → Пошаговый разбор → Edge cases → Мифы → Связи → Q&A → Что почитать** (см. `Шаблон-deep-dive.md`). К deep-dive правило шестёрки секций НЕ применяется.
- Объём 3000–5000 слов основного тела.
- В обычном уроке-«родителе» в секции «Что почитать» **первой строкой** — wiki-link на свой deep-dive (это формальная связь между двумя слоями).

## Frontmatter и wiki-links

Все заметки начинаются с YAML frontmatter. Минимальный набор полей у урока:

```yaml
---
модуль: NN-название-модуля
тема: Тема урока
статус: to-read    # to-read | in-progress | done
roadmap: https://roadmap.sh/frontend
связано: "[[другая-заметка]], [[ещё-одна]]"
---
```

Поля кириллицей — это сознательное решение. Не переименовывай в `module/topic/status`, иначе сломаются Dataview-запросы и существующие связи.

Связи между заметками — только Obsidian wiki-links `[[имя-файла]]` или `[[путь/к/файлу|видимый текст]]`. Прежде чем вставить ссылку — убедись, что целевой файл существует (в коммите `bdff86a` уже чинились битые wiki-link'и).

## Работа над контентом

В `docs/superpowers/` — рабочие артефакты для генерации курса:
- `specs/` — design-спеки (общая концепция курса).
- `plans/` — пошаговые планы реализации модулей (`YYYY-MM-DD-frontend-course-module-NN.md` для базового, `...frontend-advanced-track-N.md` для продвинутого).

При наполнении нового модуля **сначала смотри в соответствующий план в `docs/superpowers/plans/`** — там зафиксирована скоупа модуля, разбивка на уроки и пересечения с другими модулями. Если план расходится с текущим состоянием vault'а, считай vault источником истины и предупреди пользователя.

`FrontendAdvanced-dumps/` — служебные дампы прежних версий, в основной курс не подтягивать (этот каталог в `.gitignore`).

Локальное состояние Obsidian (`.obsidian/workspace.json`, `workspaces.json`, `graph.json`) тоже игнорируется git'ом — не коммить эти файлы, даже если они изменились после открытия vault'а.

## Коммиты

Стиль из недавней истории — Conventional Commits с лаконичным телом, на английском:
- `feat: add 4 new modules (A3.7, A3.8, A4.7, A6.5) — 20 new lessons`
- `fix: resolve 5 broken wiki-links in course`
- `refactor: clarify scope between A3.5/A4.5 and A5.1.4/A1.1.6/A1.3.5`

При массовых правках упоминай счётчики (сколько уроков/модулей/ссылок). Сообщения — на английском, даже когда содержимое — на русском.

## Чего не делать

- Не превращать репозиторий в код-проект: не добавляй `package.json`, билд-системы, тестовые рантаймы — здесь нет приложения.
- Не применяй Vercel/Next.js/React-инструкции к самому репозиторию. Эти технологии — **предмет курса**, а не его стек. Vercel/Next-скиллы и подсказки, которые предлагает харнесс на README, здесь не релевантны.
- Не добавляй файл целиком из шаблонного «общеразвивающего» текста LLM — урок без конкретики и реалистичного кода в этом курсе считается браком.
