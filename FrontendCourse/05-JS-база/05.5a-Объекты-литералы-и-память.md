# Объекты — литералы и ссылочная природа

## Зачем это нужно

В уроке 05.1 ты узнал про примитивы: числа, строки, булевы значения. Они ведут себя предсказуемо — если `let a = 5` и `let b = a`, то `b` получает *копию* пятёрки. Изменение `b` не затрагивает `a`. Но объекты ведут себя иначе: `let b = a` не создаёт копию, а даёт вторую *этикетку* на ту же коробку. Пока ты не увидишь эту разницу в памяти, каждая «случайная» мутация будет казаться магией бага. Этот урок — фундамент всего остального: без понимания ссылочной семантики невозможно освоить ни прототипы, ни React state, ни работу с API.

> **Опорные концепты из предыдущих уроков:** `let`/`const`, примитивные типы, `typeof`.

---

## Главное

### Объект = коллекция пар «ключ → значение"

Объект группирует связанные данные под одним именем. Пока думай о нём как о *карточке* или *записи* — без сложностей ссылочности.

```js
const user = {
  name: "Иван",
  age: 28,
  isAdmin: false
};
```

Ключи — строки (кавычки не обязательны, если имя валидный идентификатор). Значения — что угодно: число, строка, массив, другой объект.

Доступ к свойствам:
- Через точку: `user.name` — основной способ.
- Через скобки: `user["age"]` — нужен, когда ключ в переменной или содержит пробел/дефис.

```js
const key = "name";
console.log(user[key]);     // "Иван"
console.log(user["isAdmin"]); // false
```

### Модель памяти: стек vs куча

Это — ключ к пониманию. Запомни диаграмму:

```
┌─────────────────────────────────────────────┐
│  СТЕК (Stack)                               │
│  ┌─────────┐                                │
│  │  name   │ → "Иван"   ← примитив лежит   │
│  │  count  │ → 42        прямо здесь        │
│  │  user   │ ─────────┐                     │
│  └─────────┘          │                     │
│                       ▼                     │
│  ┌─────────────────────────────────────┐    │
│  │  КУЧА (Heap)                        │    │
│  │  ┌─────────────────────────────┐    │    │
│  │  │  {name: "Иван", age: 28}    │◄───┘    │
│  │  └─────────────────────────────┘         │
│  └─────────────────────────────────────┘    │
└─────────────────────────────────────────────┘
```

**Примитивы** (`number`, `string`, `boolean`, `null`, `undefined`) хранятся **прямо в стеке** — в ячейке переменной. **Объекты** создаются в **куче** (heap) — отдельной области памяти. Переменная в стеке хранит не сам объект, а **ссылку** (стрелку) на него.

### Метафора «этикетка на коробке»

- **Объект** = коробка на складе (куча).
- **Переменная** = этикетка, приклеенная к коробке.
- `let b = a` = наклеить **вторую этикетку** на ту же коробку. Коробка одна, этикеток две.
- `b.name = "Пётр"` = открыть коробку и поменять содержимое. Видно через обе этикетки.
- `b = {name: "Новый"}` = отклеить этикетку `b` и приклеить к другой коробке. Этикетка `a` по-прежнему указывает на старую.

### Предскажи вывод (Predict the output)

Перед тем как читать ответ, попробуй предсказать результат и нарисовать диаграмму памяти.

**Пример 1:**
```js
let a = { x: 1 };
let b = a;
b.x = 2;
console.log(a.x);
```

**Твой ответ:** `___`

**Диаграмма:**
```
Стек:          Куча:
a ──────────►  {x: 2}
b ──────────►  (та же коробка)
```

**Результат:** `2`. `a` и `b` — две этикетки на одной коробке. Изменение через `b` видно через `a`.

**Пример 2:**
```js
let a = { x: 1 };
let b = a;
b = { x: 99 };
console.log(a.x);
```

**Твой ответ:** `___`

**Диаграмма:**
```
Стек:          Куча:
a ──────────►  {x: 1}      ◄── осталась как была
b ─────┐                    
       └────►  {x: 99}      ◄── новая коробка
```

**Результат:** `1`. `b` отклеилась от старой коробки и приклеилась к новой. `a` никто не трогал.

### Сравнение объектов

```js
const a = { x: 1 };
const b = { x: 1 };
console.log(a === b); // false
```

`===` сравнивает **ссылки** (этикетки), не содержимое коробок. Две одинаковые коробки — это разные коробки на складе.

```js
const a = { x: 1 };
const b = a;
console.log(a === b); // true
```

Обе этикетки на одной коробке — `true`.

### Копирование: поверхностное vs глубокое

**Spread `{...obj}`** создаёт новую коробку, но копирует содержимое *по значению для примитивов и по ссылке для вложенных объектов*.

```js
const user = { name: "Иван", settings: { theme: "dark" } };
const copy = { ...user };

copy.name = "Пётр";           // OK: изменится только copy
console.log(user.name);       // "Иван" — примитив скопирован по значению

copy.settings.theme = "light"; // ОПАСНО: settings — ссылка!
console.log(user.settings.theme); // "light" — мутировал оригинал!
```

**Диаграмма поверхностной копии:**
```
Стек:               Куча:
user ───────┐      ┌─────────────────────────────┐
            ├─────►│ name: "Иван"                │
copy ───────┘      │ settings ───────┐           │
                   └─────────────────┼───────────┘
                                     ▼
                              ┌──────────────┐
                              │ theme: "light"│
                              └──────────────┘
                    (user.settings и copy.settings
                     указывают на один объект!)
```

Для **глубокого копирования** используй `structuredClone(obj)` — современный метод, который рекурсивно копирует всё:

```js
const deep = structuredClone(user);
deep.settings.theme = "light";
console.log(user.settings.theme); // "dark" — оригинал не тронут
```

> **Антипаттерн:** `JSON.parse(JSON.stringify(obj))` как deep clone. Это работает только для простых данных. Потеряет функции, `Date`, `undefined`, `Symbol`, `Map`, `Set`, `BigInt`, и упадёт на циклических ссылках.

## Пример кода

### Работа с объектом

```js
// Создание и доступ
const product = {
  id: 101,
  title: "Наушники",
  price: 4990,
  inStock: true
};

console.log(product.title);        // "Наушники"
console.log(product["price"]);     // 4990

// Добавление и изменение
product.price = 3990;
product.category = "Электроника";

// Удаление (используется редко)
delete product.inStock;

// Проверка наличия свойства
console.log("title" in product);   // true
console.log("discount" in product); // false
```

### Вычисляемые ключи и shorthand

```js
const field = "email";
const value = "ivan@example.com";

// Вычисляемый ключ
const user = {
  name: "Иван",
  [field]: value    // ключ взят из переменной
};

// Shorthand: когда переменная совпадает с именем ключа
const name = "Иван";
const age = 28;
const profile = { name, age };  // то же самое, что { name: name, age: age }
```

### Иммутабельное обновление (подготовка к React)

```js
const state = { count: 0, user: { name: "Иван" } };

// Правильно: создаём новый объект, не мутируем старый
const nextState = {
  ...state,
  count: state.count + 1
};

// Для вложенности — тоже копируем вложенный объект
const nextStateDeep = {
  ...state,
  user: { ...state.user, name: "Пётр" }
};

console.log(state.user.name);      // "Иван" — оригинал цел
console.log(nextStateDeep.user.name); // "Пётр" — новый объект
```

## Частые ошибки

**Ошибка 1: «`const` защищает объект от изменений»**

```js
const user = { name: "Иван" };
user.name = "Пётр"; // OK! const запрещает переназначить саму переменную,
                    // но не мутировать содержимое объекта
```

*Почему возникает:* студент проецирует опыт примитивов (`const x = 5; x = 6` → ошибка) на объекты. Но `const` контролирует только стрелку в стеке, не содержимое коробки в куче.

**Ошибка 2: `const copy = obj` думает, что создал копию**

```js
const a = { x: 1 };
const b = a;        // НЕ копия! Две этикетки на одной коробке
b.x = 2;
console.log(a.x);   // 2 — оригинал мутировал
```

*Почему возникает:* из опыта с примитивами, где `let b = a` действительно копирует значение.

**Ошибка 3: `JSON.stringify` как deep clone**

```js
const user = {
  name: "Иван",
  createdAt: new Date(),
  settings: { theme: "dark" }
};

const badClone = JSON.parse(JSON.stringify(user));
console.log(badClone.createdAt); // "2024-01-15T..." — строка, не Date!
```

*Почему возникает:* кажется, что «превратить в строку и обратно» = чистая копия. Но `JSON.stringify` сериализует только JSON-совместимые типы.

**Ошибка 4: Сравнение объектов через `===` ожидая проверку содержимого**

```js
const a = { x: 1 };
const b = { x: 1 };
console.log(a === b); // false — разные коробки!
```

*Почему возникает:* интуиция говорит «одинаковое содержимое = равно». Но `===` проверяет идентичность ссылок, не эквивалентность содержимого.

```js
const appState = {
  user: { id: 1, name: "Иван", role: "user" },

  notifications: [{ id: 1, text: "Привет" }]
};
```

Создай `nextState`, где:
- `ui.sidebarOpen` стал `true`
- `user.name` стал "Пётр"
- оригинальный `appState` остался неизменным
