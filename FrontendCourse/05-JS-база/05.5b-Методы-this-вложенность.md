# Методы, this и вложенные объекты

## Зачем это нужно

В реальной работе фронтендера объекты — это не статичные карточки. Это данные из API (вложенные на 3–5 уровней), состояние форм, конфигурация компонентов. Ты должен уметь: вытаскивать поля из глубоко вложенного JSON, понимать почему метод `this.name` ведёт себя по-разному в разных контекстах, и безопасно навигировать по объектам, которые могут быть неполными. Этот урок — мост между «объект как карточка» и «объект как рабочий инструмент фронтендера».

> **Опорные концепты:** объектные литералы, ссылочная природа, присваивание, spread.

---

## Главное

### Методы — функции внутри объекта

Объект может хранить не только данные, но и поведение:

```js
const user = {
  name: "Иван",
  age: 28,
  greet() {
    return `Привет, я ${this.name}!`;
  }
};

console.log(user.greet()); // "Привет, я Иван!"
```

Короткая запись `greet() { ... }` — то же самое, что `greet: function() { ... }`, но чище.

### `this` — контекст вызова, не определения

Значение `this` зависит от того, **как вызвана функция**, а не от того, где она написана.

```js
const user = {
  name: "Иван",
  greet() {
    return `Привет, ${this.name}`;
  }
};

user.greet();        // "Привет, Иван" — this = user

const fn = user.greet;
fn();                // "Привет, undefined" — this = global/window!
```

**Диаграмма:**
```
Вызов user.greet():
  this ───────► user

Вызов fn() (где fn = user.greet):
  this ───────► global/window  (или undefined в strict mode)
               (стрелка "потерялась" — метод оторвался от объекта)
```

Это — главная ловушка `this`. Когда метод передаётся как коллбэк (например, `setTimeout(user.greet, 100)`), он отрывается от объекта и теряет контекст.

**Решения:**

```js
// 1. Стрелочная функция (берёт this из окружения)
const user = {
  name: "Иван",
  greet: () => `Привет, ${this.name}` // this = внешний scope!
};

// 2. Явная привязка через bind
const boundGreet = user.greet.bind(user);
setTimeout(boundGreet, 100); // OK

// 3. Обёртка-стрелка
setTimeout(() => user.greet(), 100); // OK — стрелка не имеет своего this
```

### Вложенные объекты и навигация

API-ответы — это объекты внутри объектов внутри массивов:

```json
{
  "user": {
    "id": 1,
    "profile": {
      "name": "Иван",
      "contacts": {
        "email": "ivan@example.com",
        "phone": null
      }
    }
  },
  "posts": [
    { "id": 10, "title": "Hello" }
  ]
}
```

Доступ к глубоким полям:

```js
const data = /* ... API-ответ ... */;

// Безопасный доступ: каждый уровень проверяется
const email = data.user && data.user.profile && data.user.profile.contacts && data.user.profile.contacts.email;

// Современный синтаксис: optional chaining (?.)
const email = data.user?.profile?.contacts?.email;
// Если любой уровень undefined/null — результат undefined, не ошибка

// С дефолтным значением: nullish coalescing (??)
const phone = data.user?.profile?.contacts?.phone ?? "не указан";
```

### Деструктуризация — извлечение полей

```js
const user = {
  name: "Иван",
  age: 28,
  city: "Москва",
  settings: { theme: "dark" }
};

// Простая
const { name, age } = user;

// С переименованием
const { name: userName } = user; // userName = "Иван"

// С дефолтом
const { country = "Россия" } = user; // country = "Россия" (не было в объекте)

// Вложенная
const { settings: { theme } } = user; // theme = "dark"

// Остаток
const { name, ...rest } = user;
// rest = { age: 28, city: "Москва", settings: { theme: "dark" } }
```

### Перебор объекта

```js
const user = { name: "Иван", age: 28, city: "Москва" };

// Только собственные ключи (без прототипа) — предпочтительный способ
Object.keys(user).forEach(key => {
  console.log(key, user[key]); // "name Иван", "age 28", "city Москва"
});

// Пары [ключ, значение]
Object.entries(user).forEach(([key, value]) => {
  console.log(key, value);
});

// Только значения
Object.values(user); // ["Иван", 28, "Москва"]
```

> **Важно:** `for...in` перебирает и унаследованные свойства. Используй `Object.keys`/`Object.entries`.

### Методы и потеря this

```js
const counter = {
  count: 0,
  increment() {
    this.count++;
    return this.count;
  }
};

console.log(counter.increment()); // 1
console.log(counter.increment()); // 2

// Передача как коллбэк — ПРОБЛЕМА:
const inc = counter.increment;
inc(); // NaN! this = global, global.count = undefined, undefined++ = NaN

// Решение — стрелочная функция или bind:
const counter2 = {
  count: 0,
  increment: function() {
    this.count++;
    return this.count;
  }.bind(/* нельзя здесь, нужен другой подход */)
};

// Правильное решение для коллбэков:
const counter3 = {
  count: 0,
  increment() {
    this.count++;
    console.log(this.count);
  }
};

// Оборачиваем в стрелку
setTimeout(() => counter3.increment(), 100); // OK
```

## Частые ошибки

**Ошибка 1: `this` теряется в коллбэке**

```js
const user = {
  name: "Иван",
  logName() { console.log(this.name); }
};

setTimeout(user.logName, 100); // undefined — метод оторвался!
```

*Почему возникает:* интуиция говорит, что функция «помнит» свой объект. Но `this` определяется при вызове, а `setTimeout` вызывает функцию без объекта.

**Ошибка 2: Доступ к несуществующему вложенному свойству**

```js
const user = { profile: null };
console.log(user.profile.name); // TypeError: Cannot read property 'name' of null
```

*Почему возникает:* API может вернуть `null` вместо объекта. Всегда используй `?.` для опциональных цепочек.

**Ошибка 3: Деструктуризация undefined**

```js
const user = null;
const { name } = user; // TypeError: Cannot destructure property 'name' of 'null'
```

*Почему возникает:* деструктуризация требует, чтобы справа был объект. Сначала проверь: `const { name } = user ?? {};`

**Ошибка 4: `Object.keys` vs `for...in` — забывают про прототип**

```js
const obj = { a: 1 };
for (const key in obj) {
  console.log(key); // "a" — пока OK
}

// Но если кто-то расширил Object.prototype...
// (редко, но встречается в legacy)
Object.prototype.bad = 1;
for (const key in obj) {
  console.log(key); // "a", "bad" — неожиданно!
}
```

*Почему возникает:* `for...in` идёт по всей цепочке прототипов. `Object.keys` — только собственные ключи.

**Задание 5 — Плоские данные в дерево**

Дан массив:
```js
const flat = [
  { id: 1, parentId: null, name: "Root" },
  { id: 2, parentId: 1, name: "Child 1" },
  { id: 3, parentId: 1, name: "Child 2" },
  { id: 4, parentId: 2, name: "Grandchild" }
];
```

Преобразуй в иерархию объектов:
```js
{
  id: 1, name: "Root", children: [

    ]},
    { id: 3, name: "Child 2", children: [] }

}
```

**Задание 6 — Валидация формы как объекта**

- Возвращает объект ошибок: `{ email: "Обязательное поле", age: "Должно быть числом" }`
- Не мутирует исходный `formData`
