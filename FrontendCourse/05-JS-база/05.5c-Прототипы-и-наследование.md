# Прототипы и наследование

## Зачем это нужно

Ты уже знаешь, что объекты хранят данные и методы. Но вот вопрос: если у тебя тысяча пользователей, и у каждого есть метод `greet()`, зачем хранить тысячу копий одной и той же функции? В JavaScript есть механизм, позволяющий объектам «одалживать» методы друг у друга — это **прототипное наследование**. Понять его критически важно: без этого `class` будет казаться магией, `instanceof` — случайностью, а ошибки с `this` — необъяснимыми.

> **Опорные концепты:** объектные литералы, методы, ссылочная природа, `this`.

---

## Главное

### Проблема: дублирование методов

```js
const user1 = {
  name: "Иван",
  greet() { return `Привет, ${this.name}`; }
};

const user2 = {
  name: "Пётр",
  greet() { return `Привет, ${this.name}`; }  // та же функция!
};
```

Каждый объект хранит свою копию `greet`. Это расточительно. Хотелось бы: метод один, объекты тысячи.

### Прототип — «запасной вариант»

Каждый объект в JavaScript имеет скрытое свойство `[[Prototype]]` (доступное через `__proto__` или `Object.getPrototypeOf`). Когда ты обращаешься к свойству, а в самом объекте его нет — движок идёт в прототип, потом в прототип прототипа, и так до `null`.

```
Объект user:
┌─────────────────┐
│ name: "Иван"    │
│ [[Prototype]] ──┼──► ┌────────────────────┐
└─────────────────┘    │ greet() { ... }    │
                       │ [[Prototype]] ─────┼──► Object.prototype
                       └────────────────────┘

user.greet():
  1. Ищем greet в user → нет
  2. Идём в user.__proto__ → нашли! Вызваем greet()
  3. Внутри greet: this = user (объект, на котором вызвали)
```

Это называется **делегирование**, не копирование. Метод не скопирован в `user`, а «одолжен» у прототипа.

### Создание объекта с прототипом

```js
const userPrototype = {
  greet() {
    return `Привет, ${this.name}`;
  },
  isAdult() {
    return this.age >= 18;
  }
};

const user1 = Object.create(userPrototype);
user1.name = "Иван";
user1.age = 28;

const user2 = Object.create(userPrototype);
user2.name = "Пётр";
user2.age = 16;

console.log(user1.greet());    // "Привет, Иван"
console.log(user2.greet());    // "Привет, Пётр"
console.log(user1.isAdult());  // true
console.log(user2.isAdult());  // false
```

**Диаграмма памяти:**
```
Стек:                    Куча:
user1 ───────────────►  ┌─────────────┐
                        │ name: "Иван"│
                        │ age: 28     │
                        │ __proto__ ──┼──┐
user2 ───────────────►  │ name: "Пётр"│  │
                        │ age: 16     │  │
                        │ __proto__ ──┼──┤
                        └─────────────┘  │
                                           ▼
                        ┌─────────────────────────┐
                        │ greet() { ... }         │◄── один метод!
                        │ isAdult() { ... }       │    на всех пользователей
                        │ __proto__ ──────────────┼──► Object.prototype
                        └─────────────────────────┘
```

Оба объекта ссылаются на **один и тот же** прототип. Методы не дублируются.

### Цепочка прототипов

```js
const animalPrototype = {
  eat() { return `${this.name} ест`; }
};

const dogPrototype = {
  bark() { return `${this.name} гавкает`; }
};
Object.setPrototypeOf(dogPrototype, animalPrototype);

const rex = Object.create(dogPrototype);
rex.name = "Рекс";

console.log(rex.bark());  // "Рекс гавкает" — найдено в dogPrototype
console.log(rex.eat());   // "Рекс ест" — делегировано в animalPrototype
```

**Цепочка:**
```
rex ──► dogPrototype ──► animalPrototype ──► Object.prototype ──► null

rex.bark():
  rex → нет → dogPrototype → нашли!

rex.eat():
  rex → нет → dogPrototype → нет → animalPrototype → нашли!

rex.toString():
  rex → нет → dogPrototype → нет → animalPrototype → нет
  → Object.prototype → нашли!
```

### Проверка принадлежности цепочке

```js
console.log(dogPrototype.isPrototypeOf(rex));        // true
console.log(animalPrototype.isPrototypeOf(rex));     // true
console.log(Object.prototype.isPrototypeOf(rex));    // true
```

### Собственные vs унаследованные свойства

```js
console.log(Object.keys(rex));           // ["name"] — только собственные

for (const key in rex) {
  console.log(key); // "name", "bark", "eat", "toString"...
}

// Безопасный перебор:
for (const key in rex) {
  if (rex.hasOwnProperty(key)) {
    console.log(key); // только "name"
  }
}
```

`Object.keys`, `Object.values`, `Object.entries` — только собственные свойства. `for...in` — все, включая прототип. Поэтому предпочитай `Object.keys`.

### Почему массивы и строки «умеют» методы

```js
const arr = [1, 2, 3];
arr.map(x => x * 2);  // откуда взялся map?
```

`arr` не имеет собственного свойства `map`. Но `arr.__proto__ === Array.prototype`, а `Array.prototype.map` — это метод. Вот откуда.

```js
const str = "hello";
str.toUpperCase();    // откуда toUpperCase?
```

`str.__proto__ === String.prototype`. Вся «магия» встроенных методов — это прототипы.

**Диаграмма:**
```
arr: [1, 2, 3]
  __proto__ ──► Array.prototype
                  map, filter, reduce, forEach...
                  __proto__ ──► Object.prototype
                                  toString, valueOf...
                                  __proto__ ──► null
```

## Пример кода

### Создание иерархии без классов

```js
// Базовый прототип
const vehiclePrototype = {
  move() { return `${this.name} движется`; },
  stop() { return `${this.name} остановился`; }
};

// Промежуточный прототип
const carPrototype = {
  honk() { return `${this.name}: бип-бип!`; },
  move() { return `${this.name} едет по дороге`; }  // переопределение!
};
Object.setPrototypeOf(carPrototype, vehiclePrototype);

// Конкретный объект
const myCar = Object.create(carPrototype);
myCar.name = "Жигули";

console.log(myCar.move());  // "Жигули едет по дороге" — из carPrototype
console.log(myCar.stop());  // "Жигули остановился" — делегировано из vehiclePrototype
console.log(myCar.honk());  // "Жигули: бип-бип!" — из carPrototype

// Проверка цепочки
console.log(vehiclePrototype.isPrototypeOf(myCar)); // true
console.log(carPrototype.isPrototypeOf(myCar));     // true
```

### Динамическое расширение прототипа

```js
const users = [
  Object.create(userPrototype),
  Object.create(userPrototype)
];

// Позже добавили новый метод — он сраза доступен всем!
userPrototype.logout = function() {
  return `${this.name} вышел`;
};

console.log(users[0].logout()); // "Иван вышел"
```

Это мощь и опасность прототипов: изменение прототипа влияет на все объекты, которые его используют.

### Паттерн «фабрика» с прототипами

```js
function createUser(name, age) {
  const user = Object.create(userPrototype);
  user.name = name;
  user.age = age;
  return user;
}

const u1 = createUser("Иван", 28);
const u2 = createUser("Мария", 22);
```

## Частые ошибки

**Ошибка 1: Думать, что прототип — это «наследование в Java-стиле»**

В Java класс — чертёж, объект — экземпляр. В JS нет разделения: любой объект может быть прототипом для другого. Это **делегирование**, не классическое наследование.

**Ошибка 2: Забыть, что `this` в прототипе указывает на вызывающий объект**

```js
const proto = {
  name: "Прототип",
  log() { console.log(this.name); }
};

const obj = Object.create(proto);
obj.name = "Объект";
obj.log(); // "Объект", не "Прототип"!
```

*Почему возникает:* кажется, что `log` «принадлежит» прототипу, но `this` определяется при вызове.

**Ошибка 3: Изменить прототип после создания объектов — неожиданные побочные эффекты**

```js
const proto = { x: 1 };
const a = Object.create(proto);
const b = Object.create(proto);

proto.x = 999;
console.log(a.x, b.x); // 999, 999 — оба изменились!
```

*Почему возникает:* прототип — общий. Изменение видно всем, кто на него ссылается.

**Ошибка 4: Циклические прототипы**

```js
const a = {};
const b = {};
Object.setPrototypeOf(a, b);
Object.setPrototypeOf(b, a); // TypeError: Cyclic __proto__ value
```

### ✏️ Практика

**Задание 4 — Trace by hand**

Дана цепочка:
```js
const animal = { eat: () => "eat" };
const bird = { fly: () => "fly" };
Object.setPrototypeOf(bird, animal);
const penguin = { swim: () => "swim" };
Object.setPrototypeOf(penguin, bird);
```

Проследи путь поиска:
1. `penguin.swim()` — где найдено?
2. `penguin.fly()` — где найдено?
3. `penguin.eat()` — где найдено?
4. `penguin.run()` — что произойдёт?

Нарисуй цепочку и проверь в DevTools.

**Задание 5 — Плагин-система через прототипы**

Создай объект `app` с базовым прототипом, содержащим `log(message)`. Реализуй систему плагинов:

```js
const app = createApp();
app.use(loggerPlugin);  // добавляет метод logToFile()
app.use(metricsPlugin); // добавляет trackEvent(name)
```

Каждый плагин расширяет прототип `app`. Проверь, что все методы доступны и `this` работает корректно.

**Задание 6 — Рефакторинг дублирования**

Дан код:
```js
const user1 = { name: "Иван", greet() { return `Hi ${this.name}`; } };
const user2 = { name: "Пётр", greet() { return `Hi ${this.name}`; } };
const user3 = { name: "Мария", greet() { return `Hi ${this.name}`; } };
```

Перепиши, используя `Object.create` и общий прототип. Убедись, что `user1.greet()` и `user2.greet()` работают корректно и `user1.greet !== user2.greet` (то есть это один и тот же метод в прототипе).
