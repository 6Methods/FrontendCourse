# Классы как синтаксический сахар

## Зачем это нужно

Ты уже знаешь, как работают прототипы: `Object.create`, цепочки `__proto__`, делегирование методов. Это мощно, но многословно. В реальной разработке ты будешь писать `class` — он чище, компактнее и знаком большинству разработчиков. Но `class` в JavaScript — это **не новая парадигма**, а синтаксический сахар над прототипами. Цель этого урока: перестать бояться прототипов и осознанно использовать классы, понимая, что происходит под капотом.

> **Опорные концепты:** прототипы, `Object.create`, цепочки прототипов, `this`.

---

## Главное

### `class` — красивая обёртка

Вот прототипный подход, который ты уже знаешь:

```js
function User(name, age) {
  this.name = name;
  this.age = age;
}

User.prototype.greet = function() {
  return `Привет, ${this.name}`;
};

User.prototype.isAdult = function() {
  return this.age >= 18;
};

const ivan = new User("Иван", 28);
ivan.greet(); // "Привет, Иван"
```

А вот тот же код через `class`:

```js
class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Привет, ${this.name}`;
  }

  isAdult() {
    return this.age >= 18;
  }
}

const ivan = new User("Иван", 28);
ivan.greet(); // "Привет, Иван"
```

**Результат в памяти идентичен.** `constructor` — это функция `User`. Методы `greet` и `isAdult` — это `User.prototype.greet` и `User.prototype.isAdult`.

**Диаграмма:**
```
class User {          function User(name, age) {
  constructor(...)        this.name = name;
  greet() {...}      }    User.prototype.greet = ...
  isAdult() {...}         User.prototype.isAdult = ...
}

        │                          │
        └─────────── ОДНО И ТО ЖЕ ─┘
        (в памяти)
```

### Параллель: что к чему

| `class` | Прототипный эквивалент |
|---------|----------------------|
| `constructor(name) { this.name = name; }` | `function User(name) { this.name = name; }` |
| `greet() { ... }` | `User.prototype.greet = function() { ... }` |
| `static createGuest()` | `User.createGuest = function() { ... }` |
| `extends Parent` | `Object.create(Parent.prototype)` + установка `constructor` |
| `super(name)` | `Parent.call(this, name)` |

### Статические методы

Статические методы принадлежат **классу**, не экземпляру:

```js
class User {
  constructor(name) {
    this.name = name;
  }

  static createGuest() {
    return new User("Гость");
  }

  static validateName(name) {
    return name.length >= 2;
  }
}

const guest = User.createGuest();       // OK
const valid = User.validateName("Иван"); // true
// guest.validateName("Иван")           // TypeError! validateName не на экземпляре
```

**Прототипный эквивалент:**
```js
function User(name) {
  this.name = name;
}

User.createGuest = function() {
  return new User("Гость");
};
```

### Наследование через `extends`

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  move() {
    return `${this.name} движется`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);        // ← вызов конструктора Animal
    this.breed = breed;
  }

  bark() {
    return `${this.name} лает`;
  }

  move() {
    return `${super.move()} быстро`;  // ← вызов родительского метода
  }
}

const rex = new Dog("Рекс", "Овчарка");
rex.bark();  // "Рекс лает"
rex.move();  // "Рекс движется быстро"
```

**Что происходит под капотом:**
```
Dog.prototype ──► Animal.prototype ──► Object.prototype ──► null

rex.__proto__ === Dog.prototype
Dog.prototype.__proto__ === Animal.prototype
```

`extends` делает ровно то, что ты делал руками через `Object.create` — связывает прототипы.

### Поля класса и приватные поля

```js
class Counter {
  // Поле экземпляра
  count = 0;

  // Приватное поле (начинается с #)
  #history = [];

  increment() {
    this.count++;
    this.#history.push(this.count);
    return this.count;
  }

  getHistory() {
    return [...this.#history];
  }
}

const c = new Counter();
c.increment();
c.increment();
console.log(c.count);       // 2 — публичное поле
console.log(c.getHistory()); // [1, 2]
// console.log(c.#history);  // SyntaxError! Приватное поле
```

Приватные поля `#` — это **реальная защита**, не соглашение. Движок бросает ошибку при попытке доступа снаружи. В прототипном коде приватность эмулируется через замыкания (сложнее и дороже по памяти).

### Геттеры и сеттеры

```js
class Rectangle {
  constructor(width, height) {
    this.width = width;
    this.height = height;
  }

  get area() {
    return this.width * this.height;
  }

  get isSquare() {
    return this.width === this.height;
  }
}

const r = new Rectangle(4, 5);
console.log(r.area);     // 20 — выглядит как свойство!
console.log(r.isSquare); // false
```

`get area()` — это метод, который вызывается при чтении `r.area`. Удобно, когда хочешь спрятать вычисления за простым интерфейсом.

## Пример кода

### Двунаправленный рефакторинг

**Прототип → Класс:**
```js
// Было
function Product(name, price) {
  this.name = name;
  this.price = price;
}
Product.prototype.getInfo = function() {
  return `${this.name}: ${this.price}₽`;
};
Product.prototype.applyDiscount = function(percent) {
  this.price = this.price * (1 - percent / 100);
};

// Стало
class Product {
  constructor(name, price) {
    this.name = name;
    this.price = price;
  }

  getInfo() {
    return `${this.name}: ${this.price}₽`;
  }

  applyDiscount(percent) {
    this.price = this.price * (1 - percent / 100);
  }
}
```

**Класс → Прототип (чтобы увидеть, что нет магии):**
```js
// Дан класс
class Animal {
  constructor(name) { this.name = name; }
  speak() { return `${this.name} издаёт звук`; }
}

// Это то же самое:
function Animal(name) {
  this.name = name;
}
Animal.prototype.speak = function() {
  return `${this.name} издаёт звук`;
};
```

### Практический пример: форма с валидацией

```js
class FormField {
  constructor(name, value = "", required = false) {
    this.name = name;
    this.value = value;
    this.required = required;
    this.errors = [];
  }

  validate() {
    this.errors = [];
    if (this.required && !this.value.trim()) {
      this.errors.push("Обязательное поле");
    }
    return this.errors.length === 0;
  }

  get isValid() {
    return this.errors.length === 0;
  }
}

class EmailField extends FormField {
  validate() {
    const baseValid = super.validate();
    if (this.value && !this.value.includes("@")) {
      this.errors.push("Некорректный email");
    }
    return baseValid && this.isValid;
  }
}

const email = new EmailField("email", "", true);
email.validate();
console.log(email.errors); // ["Обязательное поле"]

const email2 = new EmailField("email", "invalid", true);
email2.validate();
console.log(email2.errors); // ["Некорректный email"]
```

## Частые ошибки

**Ошибка 1: Забыть `new`**

```js
const u = User("Иван", 28); // без new!
console.log(u);             // undefined
console.log(name);          // "Иван" — засорили глобальный объект!
```

*Почему возникает:* без `new` функция-конструктор работает как обычная функция. `this` внутри — `global`/`window` (или `undefined` в strict mode).

**Ошибка 2: `this` до `super()` в наследнике**

```js
class Dog extends Animal {
  constructor(name, breed) {
    this.breed = breed;  // ReferenceError! this ещё не существует
    super(name);
  }
}
```

*Почему возникает:* `super()` создаёт `this`. До него обращаться к `this` нельзя.

**Ошибка 3: Стрелочные методы vs обычные**

```js
class Button {
  label = "Нажми";

  // Обычный метод — на прототипе, теряет this
  handleClick() { console.log(this.label); }

  // Стрелочное поле — на экземпляре, сохраняет this
  handleArrow = () => { console.log(this.label); }
}

const b = new Button();
setTimeout(b.handleClick, 10);  // undefined — this потерян
setTimeout(b.handleArrow, 10);  // "Нажми" — this сохранён
```

*Почему возникает:* обычный метод живёт на прототипе, `this` определяется при вызове. Стрелочное поле создаётся в конструкторе и запоминает `this` через замыкание — но каждый экземпляр хранит свою копию функции.

**Ошибка 4: Думать, что класс = статический тип**

```js
class User {
  constructor(name) { this.name = name; }
}

const u = new User("Иван");
u.age = 28; // OK! Поля можно добавлять динамически
```

*Почему возникает:* класс в JS — это не жёсткий контракт. Объект всё ещё динамичен, как и любой другой объект.

**Задание 4 — Рефакторинг в обе стороны**

Дан прототипный код:
```js
function Task(title) {
  this.title = title;
  this.done = false;
}
Task.prototype.toggle = function() {
  this.done = !this.done;
};
Task.prototype.toString = function() {
  return `[${this.done ? "x" : " "}] ${this.title}`;
};
```

Перепиши на `class`. Затем, не подсматривая, восстанови прототипную версию из `class`.

**Задание 5 — Иерархия компонентов**

Создай иерархию:
- `Component` — базовый класс с `constructor(props)` и методом `render()`
- `Button extends Component` — добавляет `onClick` и переопределяет `render()`
- `IconButton extends Button` — добавляет `icon` и расширяет `render()`

Проверь цепочку прототипов в DevTools: `iconButton.__proto__`, `Button.prototype.__proto__`.

**Задание 6 — Объясни под капотом**

Дан код:
```js
class MyArray extends Array {
  static get [Symbol.species]() {
    return Array;
  }
}
const a = new MyArray(1, 2, 3);
const b = a.map(x => x * 2);
console.log(b instanceof MyArray);
console.log(b instanceof Array);
```

Что выведет и почему? Как `Symbol.species` связан с прототипной цепью?
