# Тема урока — глубокое погружение

> Этот урок — второй слой под [[NN.X-поверхностный-урок]]. Поверхностный урок отвечает на вопрос «что это и как им пользоваться». Этот — на вопрос «что именно происходит в рантайме / на уровне спецификации, чтобы это работало», и закрывает edge cases уровня senior-собеседования.

## Назначение и применение

**Когда писать deep-dive.** Только для тем, где базового урока физически не хватает: JS-внутренности, рендер браузера, React-reconciliation, реактивность, TS type-system, system design, продвинутые алгоритмические темы. Для большинства уроков deep-dive не нужен.

**Имя файла.** `NN.X-Тема-deep.md` рядом с поверхностным `NN.X-Тема.md`. Не выносить в отдельную папку.

**Frontmatter.** Поле `тип: deep-dive` обязательно — это формальный признак второго слоя для будущих Dataview-запросов. Остальные поля — как у обычного урока.

**Связь с поверхностным уроком.** В «Что почитать» поверхностного урока первой строкой — wiki-link на свой deep-dive с пометкой объёма («≈45 минут»). Без этого студент не узнает, что второй слой существует.

**Структура — другая, чем у обычного урока.** Шестёрка `Зачем → Главное → Пример кода → Частые ошибки → Задания → Что почитать` НЕ применяется. Вместо неё — структура ниже. Не объединяй секции, не добавляй новые верхнеуровневые разделы — единообразие deep-dive'ов на это рассчитывает.

**Объём.** 3000–5000 слов основного тела (без учёта кода и Q&A).

## Модель: как это работает на самом деле

[Единая ментальная модель темы. 400–800 слов. Эта секция должна сделать последующие edge cases предсказуемыми, а не удивляющими. Используй спецификационную терминологию (ECMA-262, WHATWG, RFC), но переводи её на человеческий язык — в скобках или через таблицу. Если в индустрии есть несколько конкурирующих моделей — выбери одну и обоснуй; альтернативы упомяни в сноске.

Диаграмма (mermaid или ASCII) **обязательна**, если тема включает state transitions, scope chains, deps graphs, runtime stages, async-стадии. Если тема линейная — без диаграммы.]

## Пошаговый разбор примера

[Один реалистичный пример (production-like, не foo/bar — например, hook с подпиской на WebSocket, debounce у поля поиска, useEffect с race condition, сетевой ретрай с экспоненциальным backoff). Покажи код целиком, потом построчно/посекционно объясни, что происходит в рантайме. Цель — чтобы читатель умел в голове «проиграть» любой подобный код.

500–900 слов с кодом. Если пример требует TypeScript — пиши на TS, не упрощай в JS. Финальный абзац — «Что отсюда забираем»: 2–3 правила-вывода.]

## Edge cases и почему они себя так ведут

[8–15 edge cases, отсортированных по частоте в проде. Для каждого:

- Минимальный воспроизводимый код (реальный, не abstract foo/bar)
- **Ожидание:** что думает большинство разработчиков
- **Реальность:** что происходит на самом деле
- **Объяснение:** через ментальную модель из секции «Модель»

80–150 слов на случай плюс код. Не повторяй то, что есть в поверхностном уроке.]
