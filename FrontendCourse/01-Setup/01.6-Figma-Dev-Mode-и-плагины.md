# Figma Dev Mode и плагины-мосты

## Зачем это нужно

Самый частый стопор у дизайнера в начале курса — «я ничего ещё не выучил, я не могу написать код». Это неправда: 60% CSS можно вытащить из своих макетов **прямо сейчас**, не зная синтаксиса. Figma встроила в себя Dev Mode и позволяет плагинам генерировать стартовый код одной кнопкой. Этот урок — про то, как ими пользоваться, чтобы получить первый практический результат уже сегодня, и одновременно — где их потолок и почему всё равно нужно учиться CSS дальше.

## Главное

### Figma Dev Mode: что это

Dev Mode — это вторая «вкладка» в правой панели Figma (иконка с галочкой `</>` в правом верхнем углу). Бесплатный тариф открывает Inspect Panel — упрощённую версию: размеры, отступы, шрифты, цвета, готовый CSS любого слоя. Платный Dev seat добавляет сверху: аннотации, статусы готовности (Ready for dev, In progress), сравнение версий, плагины внутри Dev Mode, экспорт ассетов в нужном формате.

Для целей этого курса хватит **Inspect-панели бесплатного плана**. Кнопка «Code» внизу панели даёт CSS-код любого выбранного слоя — это и есть то, что нужно.

### Что Dev Mode делает за тебя

Кликни на любой слой в Figma и переключись на Inspect/Dev Mode. Получишь готовый блок CSS:

```css
/* Кнопка из макета */
display: flex;
padding: 12px 24px;
justify-content: center;
align-items: center;
gap: 8px;
border-radius: 8px;
background: #3B82F6;
color: #FFFFFF;
font-family: Inter;
font-size: 16px;
font-weight: 600;
line-height: 24px;
```

Скопируй, вставь в свой `style.css` под нужный селектор, обнови страницу — кнопка из макета появится в браузере. Серьёзно, это всё. Никакой магии не будет, потому что её и в коде нет.

Dev Mode также показывает: **Variables** (если ты настроил их в Figma — токены цветов и отступов попадут в CSS как `var(--color-primary)`), **измерения между объектами** (хочешь узнать отступ — выдели два слоя), **Assets** (экспорт SVG/PNG прямо отсюда), **переменные шрифтов** в формате CSS-стиля.

### Чего Dev Mode НЕ делает

Этот раздел важнее предыдущего. Dev Mode даёт стиль одного слоя, но он:

- **Не понимает иерархию**. Если у тебя 10 одинаковых кнопок в макете, Dev Mode 10 раз даст одинаковый CSS вместо «вот компонент `Button` и используй его». Принимать решения о реиспользовании надо самому.
- **Не делает адаптив**. CSS, который ты получил, будет работать на одном размере экрана. Чтобы блок ужимался на мобильном — учиться `flex-wrap`, `media queries`, `min/max-width`. Это уже модуль 03.
- **Не знает о твоей design system в коде**. Если в проекте у тебя уже подключен Tailwind или своя библиотека — Dev Mode выдаст «сырой» CSS, а ты потом будешь переводить его в Tailwind-классы. Плагины Figma to Tailwind частично это решают.
- **Хорош в Auto layout, плох в произвольных слоях**. Если ты собирал макет на abolute-позиционировании в обычном Frame, CSS получится корявый и труднопереиспользуемый. Чем чище auto layout в Figma, тем чище код в Dev Mode.

### Плагины-генераторы кода

Кроме встроенного Dev Mode есть плагины, которые делают шаг дальше: генерируют не только CSS, а целый компонент в HTML/React/Vue/SwiftUI.

**Главные имена:**

- **Anima** — Figma → React/Vue/HTML. Поддерживает auto layout как Flex, экспорт в готовый репозиторий. Один из старейших.
- **Locofy.ai** — Figma → React/Next.js/HTML с настройкой адаптива и взаимодействий. Активно использует AI для имён и структуры.
- **Builder.io for Figma** — Figma → React с AI, плюс визуальный редактор поверх кода.
- **TeleportHQ** — Figma → HTML/CSS, проще, без React-обвязки.
- **html.to.design** — обратное направление: возьми существующий сайт и затащи его в Figma как макет. Полезно, когда нужно «почистить и редизайнить».

**Как использовать:** выбери макет → запусти плагин из меню Plugins → Run → выбери экспорт → скачай как ZIP или отправь в проект. Большинство имеют бесплатный лимит на 1–3 экрана/проекта.

**Их потолок (читай внимательно):**

- Имена классов мусорные: `frame-1`, `text-23`, `Group-9`. Перед использованием их надо переименовать руками в осмысленные.
- Адаптив всегда хуже, чем сделанный руками. Часто нужно полностью переписать flex-структуру.
- Компоненты не реиспользуются между экранами: одна и та же карточка экспортируется как 5 разных HTML-блоков. Снова — ручная работа.
- AI-генерация **похожа на правду**, но не **гарантирована**: бывают глюки, бывают потери стилей, бывает «всё хорошо, кроме того, что сломан hover».

Сгенерированный код — это **стартовая точка**, не финальный код. На реальный проект его нужно переписать на 50–80%. Но эта стартовая точка экономит первые часы, и видеть, как выглядит код, который соответствует твоему макету — отличный способ учиться.

### Почему всё равно нужно знать CSS

Эта секция здесь, чтобы ты не закрыл курс с мыслью «зачем мне CSS, я плагином сгенерирую». Три причины, почему этого не хватит:

1. **Подправить, что сгенерилось** — невозможно без понимания box model и flex. Сгенерированный отступ съезжает — ты не починишь, не зная, что такое padding vs margin.
2. **Адаптив** — генераторы делают плохо, всегда. Без понимания media queries и flex-wrap ты застрянешь на первом мобильном экране.
3. **Долгосрочно** — макет меняется. Если ты только умеешь жать кнопку «сгенерировать», ты каждый раз генеришь заново и теряешь все правки. Если умеешь править руками — кор экспорта обновляешь только то, что изменилось.

Dev Mode и плагины — это **ускорители для тех, кто понимает CSS**. Для тех, кто не понимает — это костыль, на котором далеко не уйдёшь.

## Пример кода

Рабочий процесс «макет в Figma → живая страница» от начала до конца. Делается за 15 минут, даёт первый осязаемый результат.

**Шаг 1.** В Figma создай (или открой существующий) frame: карточка с заголовком, описанием и кнопкой. Используй auto layout, padding, gap, corner radius — всё как обычно.

**Шаг 2.** Кликни на корневой frame карточки → открой Inspect/Dev Mode → нажми «Copy as CSS» (или просто скопируй блок CSS из панели).

**Шаг 3.** Создай на Рабочем столе папку `card-test`, в ней файл `index.html`:

```html
<!doctype html>
<html lang="ru">
<head>
  <meta charset="utf-8" />
  <title>Карточка из Figma</title>
  <style>
    body {
      margin: 0;
      padding: 40px;
      background: #f5f5f5;
      font-family: system-ui, sans-serif;
    }

    .card {
      /* СЮДА вставь CSS, скопированный из Figma Dev Mode */
    }

    .card h2 {
      /* CSS заголовка из Dev Mode */
    }

    .card p {
      /* CSS описания из Dev Mode */
    }

    .card button {
      /* CSS кнопки из Dev Mode */
    }
  </style>
</head>
<body>
  <article class="card">
    <h2>Заголовок карточки</h2>
    <p>Описание из макета. Может быть в две-три строки.</p>
    <button>Действие</button>
  </article>
</body>
</html>
```

**Шаг 4.** Открой `index.html` в браузере (двойной клик). Ты увидишь карточку, очень похожую на макет.

**Шаг 5.** Сравни с Figma. Найди три различия — и попробуй понять, что добавить в CSS, чтобы сделать одинаково. Не получится сразу — это нормально, на эти вопросы отвечают модули 02–04.

Этот эксперимент даёт тебе **точное ощущение масштаба**: что в коде уже бесплатно, что предстоит выучить, и как далеко CSS от Figma на самом деле. Спойлер: ближе, чем кажется.

## Частые ошибки

- **Доверять автогенерированному адаптиву.** Плагин выдал код, на десктопе всё работает — а на мобиле всё съехало. Адаптив надо проверять руками на узких размерах окна (просто потяни границу браузера) и читать модуль 03.6 про media queries.
- **Не настраивать Variables в Figma.** Если у тебя цвета и отступы — хардкод (`#3B82F6`, `16px`), Dev Mode выдаст хардкод. Настрой Local Variables в Figma — Dev Mode сразу начнёт использовать `var(--color-primary)` в CSS, и твой код будет тематизируемым.
- **Использовать имена классов из плагинов как финальные.** `frame-1`, `Group-9`, `text-23` — это шум. Переименовывай в осмысленное (`.product-card`, `.cta-button`) сразу при экспорте. Иначе через месяц не разберёшься.
- **Считать сгенерированный код «готовым проектом».** Это стартовая точка для одного экрана. Сайт из 5 экранов не получится склеить «прогнал через Locofy → задеплоил». Реиспользование, маршрутизация, состояния — это всё человеческая инженерия.
- **Игнорировать Dev Mode «потому что он платный».** Бесплатный Inspect Panel даёт 90% того, что нужно для учебных целей курса. Платное Dev seats добавляет аннотации и плагины, но без них тоже хорошо.

## Задания

- [ ] Открой свой Figma-проект (если нет — возьми любой бесплатный шаблон с Figma Community), переключись в Inspect/Dev Mode. Скопируй CSS любого блока. Открой в файле `index.html` (как в примере) — сравни с макетом. Найди три различия.
- [ ] Установи плагин **Locofy** или **Anima**. Сгенерируй HTML/CSS для одного экрана из своего макета. Скачай ZIP, открой `index.html` в браузере. Заметь, что не работает (адаптив, повторяющиеся блоки, мусорные имена классов). Это наглядно показывает потолок генераторов.
- [ ] Если у тебя в Figma ещё нет Local Variables — создай хотя бы одну (например, `--color-primary` для основного цвета бренда). Применяй её в макете вместо прямого hex'a. Снова открой Dev Mode — увидишь, что CSS теперь использует `var(--color-primary)` вместо `#3B82F6`.
- [ ] (Опционально) В Figma открой Dev Mode → Plugins → попробуй один из встроенных code-генераторов (например, Tailwind CSS plugin), посмотри, как тот же блок выглядит на Tailwind вместо обычного CSS.
