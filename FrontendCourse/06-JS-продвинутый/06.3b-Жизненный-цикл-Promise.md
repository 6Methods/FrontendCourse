# Жизненный цикл Promise в памяти

## Зачем это нужно

Ты уже умеешь создавать Promise и цеплять `.then`. Но что происходит **в памяти**, когда вызываешь `new Promise`? Где хранится состояние? Почему `.then` не запускает колбэк сразу? Без понимания этого промисы остаются «магией», а отладка асинхронных багов превращается в угадывание. Этот урок покажет Promise как объект в куче — так же, как мы разобрали объекты и замыкания.

> **Опорные концепты:** объекты по ссылке, scope chain, callback-функции.

---

## Главное

### Promise — объект в куче

```js
const p = new Promise((resolve, reject) => {
  resolve(42);
});
```

**Диаграмма:**
```
Стек:               Куча:
p ──────────────►  +------------------------+
                   | Promise object           |
                   |   state: "fulfilled"     |
                   |   value: 42              |
                   |   handlers: []           |
                   +------------------------+
```

Promise — обычный объект. У него есть внутренние слоты:
- `[[PromiseState]]` — `pending` | `fulfilled` | `rejected`
- `[[PromiseResult]]` — значение или ошибка
- `[[PromiseFulfillReactions]]` — очередь обработчиков `.then`
- `[[PromiseRejectReactions]]` — очередь обработчиков `.catch`

### Executor вызывается синхронно

```js
console.log("A");
const p = new Promise((resolve) => {
  console.log("B");     // синхронно!
  resolve(42);
  console.log("C");     // тоже синхронно!
});
console.log("D");
// Вывод: A, B, C, D
```

**Диаграмма:**
```
Call stack:
+----------------+
| global EC      |
+----------------+

Вызов new Promise:
+----------------+
| executor()     |  <-- синхронно!
| global EC      |
+----------------+

Внутри executor:
resolve(42) вызывается:
  → Promise.state становится "fulfilled"
  → Promise.value = 42

Возврат из executor:
+----------------+
| global EC      |
+----------------+

Продолжение глобального кода:
console.log("D")
```

### `.then` регистрирует, а не выполняет

```js
const p = Promise.resolve(42);

p.then(value => {
  console.log(value); // 42
});
```

**Что происходит пошагово:**
```
1. Promise.resolve(42) создаёт Promise:
   Heap: { state: "fulfilled", value: 42, handlers: [] }

2. p.then(handler):
   - Promise уже fulfilled
   - handler добавляется в [[PromiseFulfillReactions]]
   - НО! handler не вызывается сразу
   - Вместо этого он ставится в microtask queue

3. Текущий скрипт (macrotask) завершается

4. Event loop проверяет microtask queue:
   - Находит handler
   - Кладёт его в call stack
   - Выполняет: console.log(42)
```

**Ключевой инсайт:** `.then` никогда не выполняет колбэк синхронно. Даже если Promise уже `fulfilled`, колбэк идёт в microtask queue.

### Диаграмма: resolve → then → microtask

```js
const p = new Promise((resolve) => {
  setTimeout(() => resolve("готово"), 1000);
});

p.then(value => console.log(value));
console.log("после then");
```

```
Время: t=0
  Call stack:
  +----------------+
  | global EC      |
  +----------------+

  Heap:
  +------------------------+
  | p: Promise             |
  |   state: "pending"     |
  |   value: undefined     |
  |   handlers: [handler]  |  <-- .then зарегистрировал handler
  +------------------------+

  Web APIs:
  +------------------------+
  | setTimeout(1000ms)     |  <-- таймер запущен
  +------------------------+

  Console: "после then"

Время: t=1000ms
  Web APIs:
  +------------------------+
  | setTimeout завершился  |
  +------------------------+

  Macrotask queue:
  +------------------------+
  | callback setTimeout    |
  +------------------------+

  Event loop берёт macrotask:
  Call stack:
  +------------------------+
  | setTimeout callback    |  --> вызывает resolve("готово")
  +------------------------+

  Heap (после resolve):
  +------------------------+
  | p: Promise             |
  |   state: "fulfilled"   |
  |   value: "готово"      |
  |   handlers: [handler]  |
  +------------------------+

  Microtask queue (после resolve):
  +------------------------+
  | p's then-handler       |  <-- handler поставлен в очередь!
  +------------------------+

  Event loop (после macrotask):
  +------------------------+
  | p's then-handler       |  --> console.log("готово")
  +------------------------+

  Console: "после then", "готово"
```

## Пример кода

### Синхронный resolve

```js
const p = new Promise((resolve) => {
  resolve(1);
});

p.then(v => console.log("then:", v));
console.log("sync");

// Вывод:
// sync
// then: 1
```

Даже при синхронном resolve `.then` выполняется **после** всего синхронного кода.

### Цепочка then — каждый создаёт новый Promise

```js
Promise.resolve(1)
  .then(x => x + 1)      // возвращает 2 → новый Promise(2)
  .then(x => x * 2)      // возвращает 4 → новый Promise(4)
  .then(x => console.log(x)); // 4
```

Каждый `.then` возвращает **новый** Promise. Значение из одного then передаётся в следующий.

### Ошибка пролетает до ближайшего catch

```js
Promise.resolve(1)
  .then(x => { throw new Error("Ой"); })
  .then(x => console.log("Никогда"))  // пропускается
  .catch(err => console.log(err.message))  // "Ой"
  .then(() => console.log("Продолжаем"));  // выполнится!
```

`.catch` тоже возвращает новый Promise. Если ошибка обработана — цепочка продолжается.

## Частые ошибки

**Ошибка 1: Думать, что resolve/reject останавливают выполнение**

```js
new Promise((resolve) => {
  resolve(1);
  console.log("После resolve"); // выполнится!
});
```

*Почему возникает:* `resolve` — это просто функция. Она меняет состояние Promise, но не останавливает функцию. Используй `return resolve(...)` если нужен выход.

**Ошибка 2: Создавать Promise вокруг синхронного кода без причины**

```js
// Плохо:
function getNumber() {
  return new Promise((resolve) => resolve(42));
}

// Хорошо:
function getNumber() {
  return Promise.resolve(42); // уже готовый Promise
}
```

**Ошибка 3: Не обрабатывать reject**

```js
new Promise((resolve, reject) => {
  reject(new Error("Ой"));
});
// UnhandledPromiseRejection — ошибка в консоли!
```

*Почему возникает:* всегда добавляй `.catch` или оборачивай в `try/catch` (если async/await).
