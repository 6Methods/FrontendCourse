# Практика: трассировка реального кода через event loop

## Зачем это нужно

Теория event loop проста: стек, очереди, рендер. На практике код смешивает замыкания, Promises, async/await, DOM-события и setTimeout. Этот урок — тренажёр: берём реальные паттерны из production-кода и трассируем их вручную. Если ты правильно предсказываешь порядок вывода — ты владеешь асинхронностью.

> **Опорные концепты:** Event loop, macrotask, microtask, Promise, async/await, замыкания.

---

## Главное

### Алгоритм трассировки

Для любого фрагмента кода:

```
1. Выполни ВЕСЬ синхронный код → console output
2. Запиши, что попало в Web APIs (setTimeout, fetch, DOM listeners)
3. Запиши, что попало в microtask queue (Promise.then)
4. Запиши, что попало в macrotask queue (setTimeout колбэки)
5. Текущий macrotask завершён → event loop:
   a. Выполни ВСЕ микротаски (подряд, включая вложенные)
   b. Следующий macrotask
   c. Повторяй
```

### Паттерн 1: Fetch + обработка

```js
console.log("1");
fetch('https://api.github.com/users/octocat')
  .then(r => r.json())
  .then(data => console.log("2:", data.login));
console.log("3");
```

**Трассировка:**
```
Синхронно:
  console.log("1") → 1
  fetch(...) → Promise, Web API начинает HTTP-запрос
  .then(r => ...) → регистрирует обработчик (ещё не выполняется!)
  .then(data => ...) → регистрирует следующий обработчик
  console.log("3") → 3

Текущий macrotask завершён. Стек пуст.

Когда HTTP-ответ придёт:
  1. Promise resolve'ится → then-колбэк (r => r.json()) в microtask queue
  2. Выполняем микротаску → r.json() возвращает новый Promise
  3. Следующий then (data => ...) в microtask queue
  4. Выполняем → console.log("2:", data.login) → 2: octocat

Итог: 1, 3, 2: octocat
```

### Паттерн 2: Async/await развёрнутый

```js
async function foo() {
  console.log("A");
  await Promise.resolve();
  console.log("B");
  await Promise.resolve();
  console.log("C");
}

foo();
console.log("D");
```

**Трассировка:**
```
Синхронно:
  foo() начинает выполнение:
    console.log("A") → A
    await Promise.resolve() → Promise.resolve() мгновенно resolved
    → остаток foo приостановлен, ставится в microtask queue
  console.log("D") → D

Стек пуст. Микротаски:
  1. Продолжение foo после первого await:
     console.log("B") → B
     await Promise.resolve() → остаток в microtask queue

  2. Продолжение foo после второго await:
     console.log("C") → C

Итог: A, D, B, C
```

### Паттерн 3: Замыкание + асинхронность

```js
function createTimer() {
  let count = 0;
  return () => {
    count++;
    setTimeout(() => console.log(count), 0);
  };
}

const timer = createTimer();
timer();
timer();
timer();
```

**Трассировка:**
```
Создание:
  createTimer() → closure: { count: 0, fn: () => {...} }

Вызовы (синхронно):
  timer() → count = 1, setTimeout(..., 0) → macrotask queue: [log 1]
  timer() → count = 2, setTimeout(..., 0) → macrotask queue: [log 1, log 2]
  timer() → count = 3, setTimeout(..., 0) → macrotask queue: [log 1, log 2, log 3]

Event loop:
  Итерация 1: log 1 → console: 3  (count === 3 на момент выполнения!)
  Итерация 2: log 2 → console: 3
  Итерация 3: log 3 → console: 3

Итог: 3, 3, 3
```

**Ключевой инсайт:** замыкание хранит **ссылку** на переменную, а не её копию. Все три setTimeout видят `count === 3`.

### Паттерн 4: Promise + setTimeout комбинация

```js
console.log("1");

Promise.resolve().then(() => {
  console.log("2");
  setTimeout(() => console.log("3"), 0);
});

setTimeout(() => {
  console.log("4");
  Promise.resolve().then(() => console.log("5"));
}, 0);

Promise.resolve().then(() => console.log("6"));

console.log("7");
```

**Трассировка:**
```
Синхронно: 1, 7

Microtask queue после синхронного кода: [M1, M2]
  M1: () => { console.log("2"); setTimeout(..., 0); }
  M2: () => console.log("6")

Macrotask queue после синхронного кода: [T1]
  T1: () => { console.log("4"); Promise.then(...); }

Выполняем микротаски (все!):
  M1: console.log("2") → 2
      setTimeout(..., 0) → macrotask queue: [T1, T2]
      T2: () => console.log("3")
  M2: console.log("6") → 6

Microtask queue пуста.

Следующая итерация event loop:
  Macrotask T1: console.log("4") → 4
                Promise.resolve().then(() => log "5") → microtask queue: [M3]

  Микротаски (все!):
    M3: console.log("5") → 5

Следующая итерация:
  Macrotask T2: console.log("3") → 3

Итог: 1, 7, 2, 6, 4, 5, 3
```

## Частые ошибки

**Ошибка 1: Думать, что await «ждёт» в стеке**

```js
async function test() {
  await sleep(1000);
  console.log("done");
}
```

*Почему возникает:* await НЕ блокирует стек. Функция приостанавливается, стек освобождается, event loop продолжает работу.

**Ошибка 2: Путать порядок при вложенных Promise**

```js
Promise.resolve()
  .then(() => console.log("1"))
  .then(() => console.log("2"));

Promise.resolve()
  .then(() => console.log("3"));
```

*Почему возникает:* 1, 3, 2 — первая цепочка регистрирует "1", вторая — "3". "1" выполняется, его then регистрирует "2" в ту же микротаску. Но "3" уже была в очереди раньше "2".

**Ошибка 3: Забывать, что DOM-события — macrotasks**

```js
button.click(); // синхронный вызов!
button.addEventListener('click', () => console.log("click"));
// "click" выведется сразу, если click() вызван программно
```

*Почему возникает:* программный `click()` синхронный, а пользовательский клик — macrotask.
