# От callback hell к Promise

## Зачем это нужно

Вся работа фронтендера связана с ожиданием: ответ от сервера, таймер, анимация, загрузка файла. Раньше для этого использовали колбэки — функции, которые вызываются «когда-нибудь потом». Но вложенные колбэки превращаются в «пирамиду смерти», где код уползает вправо и ошибки теряются. Promise — это не «ещё один способ», а решение конкретных проблем колбэков.

> **Опорные концепты:** функции, колбэки, замыкания.

---

## Главное

### Проблема: callback hell

```js
loadData(function(data) {
  parseData(data, function(parsed) {
    validateData(parsed, function(valid) {
      saveData(valid, function(saved) {
        console.log("Готово!");
      }, function(err) {
        console.error("Ошибка сохранения", err);
      });
    }, function(err) {
      console.error("Ошибка валидации", err);
    });
  }, function(err) {
    console.error("Ошибка парсинга", err);
  });
}, function(err) {
  console.error("Ошибка загрузки", err);
});
```

Проблемы:
- **Вложенность** — код уползает вправо
- **Обработка ошибок** — колбэк на ошибку в каждом шаге
- **Параллельность** — сложно запустить два запроса одновременно и дождаться обоих
- **Читаемость** — логика размазана по вложенным функциям

### Идея Promise: объект-обещание

Promise — это **объект**, который представляет будущее значение. У него три состояния:

```
┌─────────┐     resolve(value)     ┌──────────┐
│ pending │ ──────────────────────►│ fulfilled│
│ (ждём)  │                        │ (успех)  │
└─────────┘     reject(reason)     └──────────┘
       │
       └────────────────────────►  ┌──────────┐
                                   │ rejected │
                                   │ (ошибка) │
                                   └──────────┘
```

- `pending` — начальное состояние, значения пока нет
- `fulfilled` — операция успешна, есть `value`
- `rejected` — операция провалилась, есть `reason` (ошибка)

**Ключевое свойство:** переход происходит **один раз и навсегда**. Как только Promise стал `fulfilled` или `rejected`, изменить его нельзя.

### Создание Promise

```js
const promise = new Promise((resolve, reject) => {
  // Этот колбэк вызывается синхронно!
  console.log("Promise создан");

  setTimeout(() => {
    resolve("Данные загружены"); // переходим в fulfilled
  }, 1000);
});
```

`new Promise(executor)`:
1. Создаёт объект Promise в состоянии `pending`
2. **Синхронно** вызывает `executor(resolve, reject)`
3. Когда ты вызываешь `resolve(value)` — Promise переходит в `fulfilled`
4. Когда ты вызываешь `reject(reason)` — Promise переходит в `rejected`

### Потребление результата: .then

```js
promise.then(
  value => console.log("Успех:", value),     // onFulfilled
  reason => console.log("Ошибка:", reason)   // onRejected
);
```

`.then` **регистрирует** обработчики. Они не вызываются сразу! Они выполнятся, когда Promise перейдёт в соответствующее состояние.

### Переписываем callback hell на Promise

```js
loadData()
  .then(data => parseData(data))
  .then(parsed => validateData(parsed))
  .then(valid => saveData(valid))
  .then(saved => console.log("Готово!"))
  .catch(err => console.error("Ошибка:", err));
```

- Цепочка читается сверху вниз
- Одна `.catch` ловит ошибку на любом шаге
- Каждый `.then` получает результат предыдущего

## Пример кода

### Обёртка над setTimeout

```js
function wait(ms) {
  return new Promise(resolve => {
    setTimeout(resolve, ms);
  });
}

wait(1000)
  .then(() => console.log("Прошла секунда"))
  .then(() => wait(1000))
  .then(() => console.log("Прошло ещё секунда"));
```

### Загрузка данных

```js
function loadUser(id) {
  return new Promise((resolve, reject) => {
    fetch(`/api/users/${id}`)
      .then(res => {
        if (!res.ok) reject(new Error(`HTTP ${res.status}`));
        else resolve(res.json());
      });
  });
}

// Использование:
loadUser(1)
  .then(user => console.log(user.name))
  .catch(err => console.error("Не удалось загрузить:", err));
```

### Promise.all — параллельное выполнение

```js
Promise.all([
  fetch('/api/user').then(r => r.json()),
  fetch('/api/posts').then(r => r.json()),
])
  .then(([user, posts]) => {
    console.log("Пользователь:", user);
    console.log("Посты:", posts);
  })
  .catch(err => console.error("Один из запросов упал:", err));
```

Все промисы выполняются **параллельно**. Результат — массив значений в том же порядке.

## Частые ошибки

**Ошибка 1: Забыть `return` внутри .then**

```js
loadUser(1)
  .then(user => {
    fetchPosts(user.id); // забыли return!
  })
  .then(posts => {
    // posts === undefined, потому что предыдущий then ничего не вернул
  });
```

*Почему возникает:* каждый `.then` должен вернуть значение или Promise для следующего звена.

**Ошибка 2: Синхронные ошибки внутри new Promise без try/catch**

```js
new Promise(() => {
  throw new Error("Ой");
})
```

*Почему возникает:* синхронный `throw` внутри executor автоматически вызывает `reject`. Но если ошибка случится **после** асинхронной операции (внутри колбэка), Promise останется `pending` навсегда.

**Ошибка 3: Думать, что .then выполняется сразу**

```js
const p = Promise.resolve(42);
p.then(v => console.log(v));
console.log("После then");
// Вывод: "После then", затем "42"
```

*Почему возникает:* `.then` регистрирует обработчик, но выполнит его позже — в microtask queue.

### ✏️ Практика

**Задание 3 — Callback → Promise**

Перепиши эту функцию с колбэком на Promise:

```js
function readFile(path, callback) {
  setTimeout(() => {
    if (path.endsWith(".txt")) {
      callback(null, "Содержимое файла");
    } else {
      callback(new Error("Неправильный формат"));
    }
  }, 100);
}
```

Должно работать так:
```js
readFilePromise("file.txt")
  .then(content => console.log(content))
  .catch(err => console.error(err));
```

**Задание 4 — Promise.allSettled**

Дано три запроса, два из которых могут упасть. Используй `Promise.allSettled`, чтобы получить результаты всех — и успешных, и упавших.

```js
const requests = [
  Promise.resolve("OK"),
  Promise.reject("Fail 1"),
  Promise.resolve("OK 2")
];

// Выведи: [{status: "fulfilled", value: "OK"}, {status: "rejected", reason: "Fail 1"}, ...]
```

**Задание 5 — Параллельно с лимитом**

Напиши `promisePool(tasks, limit)` — выполняет массив функций-задач (каждая возвращает Promise), но не более `limit` одновременно.

```js
const tasks = [
  () => fetch('/api/1'),
  () => fetch('/api/2'),
  () => fetch('/api/3'),
  () => fetch('/api/4'),
];

promisePool(tasks, 2).then(results => console.log(results));
```
