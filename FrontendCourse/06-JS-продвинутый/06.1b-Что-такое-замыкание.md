# Что такое замыкание на самом деле

## Зачем это нужно

В прошлом уроке ты увидел, как функции ищут переменные по цепочке областей видимости. Теперь вопрос: что происходит, если функция **возвращается** из другой функции? Внешняя функция уже завершилась — её локальные переменные должны исчезнуть. Но если внутренняя функция всё ещё на них ссылается, движок не может их удалить. Это и есть **замыкание**.

> **Опорные концепты:** scope chain, execution context, outer lexical environment reference.

---

## Главное

### Замыкание — не фича, а побочный эффект

Замыкание — это **функция + ссылка на лексическое окружение, где она была создана**. Когда функция создаётся, движок автоматически прикрепляет к ней ссылку на текущее окружение. Это не «включается» — это происходит всегда.

```js
function outer() {
  const secret = "я живу дольше outer";

  function inner() {
    console.log(secret);
  }

  return inner;
}

const fn = outer();   // outer завершился и исчез из стека
fn();                 // но secret всё ещё доступен!
```

**Диаграмма:**
```
Шаг 1 — вызов outer():

Call stack:           Heap (куча):
+----------------+    +------------------------+
| outer() EC     |    | outer's Environment    |
| global EC      |    |   secret -> "я живу..."|
+----------------+    |   inner -> <function>  |
                      +------------------------+

Шаг 2 — outer() возвращает inner и завершается:

Call stack:           Heap (куча):
+----------------+    +------------------------+
| global EC      |    | outer's Environment    |
+----------------+    |   secret -> "я живу..."|◄── не удалено!
                      |   inner -> <function>  |    (inner на него
                      +------------------------+     ссылается)

Шаг 3 — вызов fn() (это inner):

Call stack:           Heap (куча):
+----------------+    +------------------------+
| fn() / inner   |    | outer's Environment    |
| global EC      |    |   secret -> "я живу..."|◄── fn.__closure__
+----------------+    +------------------------+

fn ищет secret:
  1. inner's Environment — нет
  2. outer's Environment (по outer reference) — нашли!
```

### Почему переменные не удаляются

JavaScript использует **сборку мусора** (garbage collection). Объект удаляется, когда на него **не остаётся ссылок**. Внешнее лексическое окружение живёт, потому что внутренняя функция хранит на него ссылку (через `[[Environment]]` или `outer lexical environment reference`).

### Метафора «сфотографированный snapshot»

Когда функция создаётся, она как будто **фотографирует** текущее окружение. Потом, куда бы её ни передали, она всегда обращается к этому «снимку».

```js
function createGreeting(greeting) {
  // greeting "зафотографирован" на момент создания inner
  return function(name) {
    return `${greeting}, ${name}!`;
  };
}

const sayHi = createGreeting("Привет");
const sayBye = createGreeting("Пока");

console.log(sayHi("Иван"));   // "Привет, Иван!"
console.log(sayBye("Иван"));  // "Пока, Иван!"
```

`sayHi` и `sayBye` — две разные функции, каждая замкнута на **своё** окружение с разным `greeting`.

### Классический подвох: цикл с `var`

```js
for (var i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 4, 4, 4
```

**Диаграмма:**
```
var i — одна переменная на всю функцию

Loop iterations:
  i = 1: setTimeout(callback1) — callback1 замыкается на i
  i = 2: setTimeout(callback2) — callback2 замыкается на ТОТ ЖЕ i
  i = 3: setTimeout(callback3) — callback3 замыкается на ТОТ ЖЕ i
  i = 4: цикл завершается

Все три колбэка смотрят на одну и ту же переменную i = 4!
```

С `let` на каждой итерации создаётся **новая** переменная:

```js
for (let i = 1; i <= 3; i++) {
  setTimeout(() => console.log(i), 0);
}
// 1, 2, 3
```

```
let i — новая переменная на каждой итерации

Loop iterations:
  i = 1: setTimeout(callback1) — callback1 замкнут на i_1 = 1
  i = 2: setTimeout(callback2) — callback2 замкнут на i_2 = 2
  i = 3: setTimeout(callback3) — callback3 замкнут на i_3 = 3

Каждый колбэк видит своё значение!
```

## Пример кода

### Фабрика счётчиков

```js
function makeCounter() {
  let count = 0;

  return {
    inc: () => ++count,
    dec: () => --count,
    get: () => count,
  };
}

const c1 = makeCounter();
const c2 = makeCounter();

c1.inc(); c1.inc();
console.log(c1.get()); // 2
console.log(c2.get()); // 0 — независимый!
```

**Диаграмма памяти:**
```
Heap:
+--------------------------------+
| makeCounter() call #1          |
|   count: 2                     |
|   inc -> <function>            |
|   dec -> <function>            |
|   get -> <function>            |
+--------------------------------+
        ▲
        │ c1 ссылается на этот объект

+--------------------------------+
| makeCounter() call #2          |
|   count: 0                     |
|   inc -> <function>            |
|   dec -> <function>            |
|   get -> <function>            |
+--------------------------------+
        ▲
        │ c2 ссылается на другой объект
```

### Приватные переменные через замыкание

```js
function createUser(name) {
  let password = "secret"; // "приватная" переменная

  return {
    getName: () => name,
    checkPassword: (guess) => guess === password,
    changePassword: (oldPass, newPass) => {
      if (oldPass === password) {
        password = newPass;
        return true;
      }
      return false;
    }
  };
}

const user = createUser("Иван");
console.log(user.getName());           // "Иван"
console.log(user.password);            // undefined — нет доступа!
console.log(user.checkPassword("secret")); // true
```

## Частые ошибки

**Ошибка 1: Думать, что замыкание — это «особая фича», которую нужно включить**

```js
function outer() {
  const x = 1;
  function inner() { console.log(x); }
  inner();
}
```

*Почему возникает:* кажется, что здесь нет замыкания, потому что `inner` вызвана сразу. Но `inner` всё равно замкнута на `outer` — просто никто не сохранил ссылку на неё после завершения `outer`.

**Ошибка 2: Ожидать, что переменная «копируется» в момент создания функции**

```js
function makeFunctions() {
  const fns = [];
  for (var i = 0; i < 3; i++) {
    fns.push(() => i);
  }
  return fns;
}

const [f0, f1, f2] = makeFunctions();
console.log(f0(), f1(), f2()); // 3, 3, 3
```

*Почему возникает:* кажется, что каждая функция запомнила значение `i` на момент создания. Нет — она запомнила **ссылку** на переменную, и все три смотрят на одну и ту же.

**Ошибка 3: Не понимать, когда замыкание мешает сборке мусора**

```js
function hugeData() {
  const bigArray = new Array(1000000).fill("x");
  return () => "small result";
}

const fn = hugeData();
// bigArray всё ещё в памяти, потому что fn замкнута на всё окружение hugeData!
```

*Почему возникает:* движок не знает, что `fn` не использует `bigArray`. Он сохраняет всё окружение целиком.

### ✏️ Практика

**Задание 4 — Нарисуй окружения**

```js
function createBankAccount(initialBalance) {
  let balance = initialBalance;

  return {
    deposit: (amount) => { balance += amount; },
    withdraw: (amount) => {
      if (amount <= balance) balance -= amount;
    },
    getBalance: () => balance
  };
}

const account = createBankAccount(100);
account.deposit(50);
account.withdraw(30);
```

Нарисуй: (1) окружение `createBankAccount`, (2) где хранится `balance`, (3) кто на него ссылается.

**Задание 5 — once()

Напиши функцию `once(fn)`, которая возвращает обёртку. Обёртка вызывает `fn` только при первом вызове и запоминает результат. При последующих вызовах возвращает сохранённый результат.

```js
const initialize = once(() => {
  console.log("Initializing...");
  return { db: "connected" };
});

const a = initialize(); // "Initializing..."
const b = initialize(); // молчит, возвращает тот же объект
console.log(a === b);   // true
```

**Задание 6 — memoize для одного аргумента**

Напиши `memoizeOne(fn)` — функцию, которая кэширует результат только для **последнего** вызова.

```js
const add = memoizeOne((a, b) => a + b);
console.log(add(2, 3)); // 5 (вычислил)
console.log(add(2, 3)); // 5 (из кэша)
console.log(add(3, 4)); // 7 (вычислил)
console.log(add(2, 3)); // 5 (вычислил снова — кэш был для 3,4)
```

Подсказка: используй замыкание для хранения последних аргументов и результата.
