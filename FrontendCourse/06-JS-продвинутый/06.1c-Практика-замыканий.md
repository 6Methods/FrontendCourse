# Практика замыканий: инкапсуляция и паттерны

## Зачем это нужно

Ты уже знаешь, что замыкание — это функция + ссылка на окружение. Теперь самое время применить это к реальным задачам. Замыкания — фундамент многих паттернов во фронтенде: приватные переменные, мемоизация, debounce/throttle, модульный паттерн, и даже React-хуки (да, `useState` работает через замыкания). Этот урок — мост от теории к профессиональному коду.

> **Опорные концепты:** scope chain, замыкание, объекты, методы.

## Главное

### Паттерн «Модуль» — приватность без классов

```js
const counterModule = (function() {
  // Приватные переменные
  let count = 0;

  // Публичный API
  return {
    increment: () => ++count,
    decrement: () => --count,
    getValue: () => count,
    reset: () => { count = 0; }
  };
})();

console.log(counterModule.getValue());  // 0
counterModule.increment();
console.log(counterModule.getValue());  // 1
// console.log(counterModule.count);    // undefined — приватно!
```

**Диаграмма:**
```
IIFE создаёт окружение:
+---------------------------+
| count: 1                  |
| increment -> <function>   │──► замкнуты на одно окружение
| decrement -> <function>   │
| getValue  -> <function>   │
| reset     -> <function>   │
+---------------------------+

Снаружи доступны только функции из возвращённого объекта.
Переменная count недоступна напрямую.
```

### Мемоизация — кэш в замыкании

```js
function memoize(fn) {
  const cache = new Map(); // кэш живёт в замыкании

  return function(...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) {
      console.log("Из кэша:", key);
      return cache.get(key);
    }
    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const slowAdd = memoize((a, b) => {
  console.log("Вычисляю...");
  return a + b;
});

console.log(slowAdd(2, 3)); // "Вычисляю..." 5
console.log(slowAdd(2, 3)); // "Из кэша: [2,3]" 5
```

`cache` — приватная переменная, недоступная снаружи. Живёт, пока жива обёрнутая функция.

### Debounce — откладывание вызова

```js
function debounce(fn, delay) {
  let timerId = null; // живёт в замыкании

  return function(...args) {
    if (timerId) clearTimeout(timerId);
    timerId = setTimeout(() => {
      fn.apply(this, args);
      timerId = null;
    }, delay);
  };
}

const handleResize = debounce(() => {
  console.log("Resize обработан!");
}, 300);

window.addEventListener("resize", handleResize);
// Вызывается много раз, но fn выполнится только через 300мс после последнего вызова
```

**Диаграмма:**
```
Вызов #1: timerId = setTimeout(..., 300)
Вызов #2 (через 100мс): clearTimeout(timerId), timerId = setTimeout(..., 300)
Вызов #3 (через 150мс): clearTimeout(timerId), timerId = setTimeout(..., 300)
...ожидаем 300мс без вызовов...
setTimeout срабатывает → fn выполняется
```

### Throttle — ограничение частоты

```js
function throttle(fn, interval) {
  let lastTime = 0;

  return function(...args) {
    const now = Date.now();
    if (now - lastTime >= interval) {
      lastTime = now;
      fn.apply(this, args);
    }
  };
}

const handleScroll = throttle(() => {
  console.log("Scroll!");
}, 1000);

window.addEventListener("scroll", handleScroll);
// Не чаще раза в секунду
```

## Пример кода

### Счётчик с историей

```js
function createCounter() {
  let count = 0;
  const history = [];

  return {
    inc() {
      count++;
      history.push({ action: "inc", count, time: Date.now() });
      return count;
    },
    dec() {
      count--;
      history.push({ action: "dec", count, time: Date.now() });
      return count;
    },
    getHistory() {
      return [...history]; // возвращаем копию, не оригинал
    }
  };
}

const c = createCounter();
c.inc(); c.inc(); c.dec();
console.log(c.getHistory());
// [{ action: "inc", count: 1, ... }, { action: "inc", count: 2, ... }, ...]
```

### Каррирование через замыкания

```js
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return function(...nextArgs) {
      return curried.apply(this, args.concat(nextArgs));
    };
  };
}

const add = curry((a, b, c) => a + b + c);
console.log(add(1)(2)(3)); // 6
console.log(add(1, 2)(3)); // 6
```

Каждый промежуточный вызов создаёт новую функцию, замкнутую на уже переданных аргументах.

## Частые ошибки

**Ошибка 1: Потеря `this` в замыкании**

```js
const user = {
  name: "Иван",
  greetDelayed() {
    setTimeout(function() {
      console.log(this.name); // undefined — this = window!
    }, 100);
  }
};
```

*Решение:* стрелочная функция берёт `this` из окружения:

```js
greetDelayed() {
  setTimeout(() => {
    console.log(this.name); // "Иван" — стрелка видит this greetDelayed
  }, 100);
}
```

**Ошибка 2: Замыкание на мутабельную переменную в цикле (var)**

```js
const buttons = [];
for (var i = 0; i < 3; i++) {
  buttons.push(() => console.log(i));
}
buttons[0](); // 3, не 0!
```

*Решение:* `let` или IIFE:

```js
for (let i = 0; i < 3; i++) { // let — новая переменная на каждой итерации
  buttons.push(() => console.log(i));
}
```

**Ошибка 3: Создание огромного замыкания без необходимости**

```js
function processData() {
  const hugeData = fetchHugeData(); // 100MB
  return () => "small result";
}
```

*Почему возникает:* движок сохраняет всё окружение, включая `hugeData`, даже если внутренняя функция его не использует.

**Задание 3 — Debounce с immediate**

Улучши `debounce` из примера: добавь параметр `immediate`. Если `immediate = true`, функция вызывается сразу при первом вызове, а потом игнорируется до таймаута.

const validator = (function() {
  const rules = []; // приватный
  // ...

**Задание 6 — React-подготовка**

Почему этот код ломается?

```js
function createHooks() {
  let state = 0;
  return {
    useState(initial) {
      if (state === 0) state = initial;
      return [state, (v) => { state = v; }];
    }
  };
}
```

Как бы ты переписал, чтобы поддерживать **несколько** состояний (массив states + индекс)? Это упрощённая модель React-хуков.
