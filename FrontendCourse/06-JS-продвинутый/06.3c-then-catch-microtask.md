# then/catch/finally и microtask queue

## Зачем это нужно

Ты знаешь, что Promise — объект с состоянием, а `.then` регистрирует обработчик. Теперь ключевой вопрос: **когда именно** выполняется этот обработчик? Ответ связывает Promise с event loop: обработчики `.then` попадают в **microtask queue** — специальную очередь, которая обрабатывается до следующего macrotask. Без понимания этого порядка невозможно предсказывать поведение асинхронного кода.

> **Опорные концепты:** Promise lifecycle, callback-функции, стек вызовов.

---

## Главное

### `.then` ставит колбэк в microtask queue

```js
Promise.resolve(1).then(v => console.log("then:", v));
console.log("sync");
// Вывод:
// sync
// then: 1
```

**Почему так?**
```
1. Синхронный код выполняется полностью (console.log("sync"))
2. Текущий macrotask (скрипт) завершается
3. Event loop забирает ВСЕ задачи из microtask queue
4. then-колбэк выполняется
5. Только потом event loop берёт следующий macrotask
```

**Диаграмма:**
```
Macrotask (текущий скрипт):
  Promise.resolve(1).then(handler)
  console.log("sync")
  → скрипт завершён

Event loop:
  ┌─────────────────────────┐
  │ Microtask queue:        │
  │   [handler: log("1")]   │
  └─────────────────────────┘
         ↓ забираем и выполняем
  console.log("then: 1")

  ┌─────────────────────────┐
  │ Macrotask queue:        │
  │   [следующий скрипт]    │
  └─────────────────────────┘
```

### Microtask vs Macrotask

|  | Microtask | Macrotask |
|--|-----------|-----------|
| **Примеры** | `Promise.then`, `queueMicrotask`, `MutationObserver` | `setTimeout`, `setInterval`, `fetch` callback, `addEventListener`, I/O |
| **Когда выполняется** | Сразу после текущего macrotask, перед рендером | По одному за итерацию event loop |
| **Приоритет** | Высокий — все микротаски выполняются до следующего macrotask | Низкий — ждут своей очереди |

**Ключевое правило:**
```
Event loop на каждой итерации:
1. Выполнить один macrotask (или скрипт)
2. Выполнить ВСЕ микротаски (пока очередь не пуста)
3. Отрендерить (если нужно)
4. Повторить
```

### Практический пример: порядок выполнения

```js
console.log("A");

setTimeout(() => console.log("B"), 0);

Promise.resolve().then(() => console.log("C"));
Promise.resolve().then(() => console.log("D"));

console.log("E");
```

**Пошаговая трассировка:**
```
Шаг 1 — синхронный код:
  console.log("A")     → A
  setTimeout(..., 0)   → регистрирует B в macrotask queue
  Promise.then(()=>C)  → регистрирует C в microtask queue
  Promise.then(()=>D)  → регистрирует D в microtask queue
  console.log("E")     → E

  Текущий macrotask завершён.

Шаг 2 — microtasks (все!):
  microtask C → console.log("C") → C
  microtask D → console.log("D") → D

  Microtask queue пуста.

Шаг 3 — следующий macrotask:
  macrotask B → console.log("B") → B

Итог: A, E, C, D, B
```

### `.catch` и `.finally`

```js
fetch('/api/data')
  .then(res => res.json())
  .catch(err => console.error("Ошибка:", err))  // ловит ошибку на любом шаге
  .finally(() => console.log("Завершено"));     // выполнится всегда
```

- `.catch(fn)` = `.then(null, fn)` — обработка ошибки
- `.finally(fn)` — выполняется в любом случае, не получает аргументов
- `.finally` тоже ставит колбэк в microtask queue

### Ошибка в `.then` пролетает до `.catch`

```js
Promise.resolve(1)
  .then(x => { throw new Error("Ой"); })
  .then(x => console.log("Пропущено"))     // пропускается
  .catch(err => console.log(err.message))  // "Ой"
  .then(() => console.log("Продолжаем"));  // выполнится — catch вернул fulfilled
```

Если `.then` бросает ошибку, следующий `.then(onFulfilled)` пропускается, а выполняется `.catch` или `.then(null, onRejected)`.

## Пример кода

### Несколько промисов и очереди

```js
console.log("1");

setTimeout(() => console.log("2"), 0);

Promise.resolve().then(() => {
  console.log("3");
  Promise.resolve().then(() => console.log("4"));
});

Promise.resolve().then(() => console.log("5"));

console.log("6");
```

**Трассировка:**
```
Синхронно: 1, 6
Microtask 1: console.log("3"), затем регистрирует "4" в microtask queue
Microtask 2: console.log("5")
Microtask 3: console.log("4")  // <-- добавлен во время обработки микротасков!
Macrotask: console.log("2")

Итог: 1, 6, 3, 5, 4, 2
```

**Важно:** если во время выполнения микротаски добавляется новая микротаска, она тоже будет выполнена в этой же итерации!

### Сравнение setTimeout(fn, 0) и Promise.then(fn)

```js
setTimeout(() => console.log("timeout"), 0);
Promise.resolve().then(() => console.log("promise"));
// Вывод: promise, timeout
```

Promise.then всегда идёт раньше setTimeout, даже с нулевой задержкой.

## Частые ошибки

**Ошибка 1: Думать, что setTimeout(0) и Promise.then — одинаково быстрые**

```js
setTimeout(() => console.log("A"), 0);
Promise.resolve().then(() => console.log("B"));
// B выведется раньше A — всегда!
```

*Почему возникает:* обе «нулевые задержки», но разные очереди. Microtasks выполняются до macrotasks.

**Ошибка 2: Бесконечный цикл микротасков**

```js
function loop() {
  Promise.resolve().then(loop);
}
loop();
```

*Почему возникает:* каждый then добавляет новую микротаску, пока предыдущая не завершится. Event loop никогда не дойдёт до рендера или macrotasks. Страница зависнет.

**Ошибка 3: Забыть return внутри .catch**

```js
fetch('/api')
  .then(r => r.json())
  .catch(err => { console.error(err); }) // нет return!
  .then(data => console.log(data));       // data === undefined
```

*Почему возникает:* `.catch` без `return` возвращает `Promise.resolve(undefined)`.
