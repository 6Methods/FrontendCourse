# Call stack, Web APIs и очереди задач

## Зачем это нужно

JS однопоточный — в один момент выполняется только одна инструкция. Но браузер асинхронный: клики мыши, ответы сервера, таймеры. Как это уживается? Event loop — координационный механизм, который позволяет одному потоку обрабатывать множество событий, не блокируясь. Понимание event loop = способность предсказывать порядок выполнения любого кода.

> **Опорные концепты:** Стек вызовов, callback-функции, Promise, setTimeout.

## Главное

### Три основных актёра

```
┌────────────────────────────────────────────────────────────┐
│                        Браузер                             │
│                                                            │
│  ┌─────────────┐    ┌──────────────┐    ┌───────────────┐ │
│  │ Call Stack  │    │   Web APIs   │    │  Task Queues  │ │
│  │             │    │              │    │               │ │
│  │  main()     │    │  setTimeout  │    │  Macrotask    │ │
│  │  foo()      │    │  fetch       │    │  Microtask    │ │
│  │  bar()      │    │  addEventListener│ │               │ │
│  │             │    │  XMLHttpReq  │    │               │ │
│  └─────────────┘    └──────────────┘    └───────────────┘ │
│         │                   │                    │         │
│         └───────────────────┴────────────────────┘         │
│                            │                               │
│                      ┌─────────┐                          │
│                      │ Event   │                          │
│                      │ Loop    │                          │
│                      └─────────┘                          │
└────────────────────────────────────────────────────────────┘
```

### Call Stack — стек вызовов

```
Стек = стопка тарелок: сверху кладём (push), сверху забираем (pop).

Вызов foo():
  [main]
  [main, foo]
  [main, foo, bar]  ← bar вызывается из foo
  [main, foo]       ← bar завершился
  [main]            ← foo завершился
```

```js
function foo() { bar(); }
function bar() { baz(); }
function baz() { console.trace(); }

foo();
```

**В DevTools:**
- Открой Sources → Call Stack при breakpoint
- Видишь `baz → bar → foo → main`

### Web APIs — работают в отдельных потоках

```js
setTimeout(() => console.log("Done"), 1000);
```

```
1. setTimeout попадает в стек
2. Браузер передаёт таймер Web API (C++ код браузера)
3. setTimeout сразу завершается, стек освобождается
4. Через 1000 мс Web API кладёт колбэк в macrotask queue
5. Event loop забирает его, когда стек пуст
```

**Диаграмма:**
```
Время →

Стек:     [setTimeout(1000)] [пусто.........] [callback]
Web API:  [таймер: 1000мс] → [таймер готов] → [кладёт в очередь]
Macro Q:  [пусто.........] [пусто.........] [callback]

Console:  (ничего)          (ничего)          "Done"
```

### Event Loop — алгоритм

```
while (true) {
  1. Если стек пуст:
     a. Взять одну задачу из macrotask queue → выполнить
     b. Выполнить ВСЕ задачи из microtask queue
     c. Отрендерить UI (если нужно)
  2. Иначе: продолжить выполнение текущей функции в стеке
}
```

**Ключевое свойство:** event loop НЕ прерывает выполнение функции. Таймер может «прозвенеть», но колбэк подождёт, пока стек освободится.

## Пример кода

### setTimeout(0) не гарантирует мгновенность

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
console.log("3");

// "1", "3", "2" — даже с нулевой задержкой!
```

**Почему:** таймер запускается, но колбэк ставится в macrotask queue. Текущий скрипт (macrotask) должен завершиться. Затем event loop берёт следующую задачу из macrotask queue.

### «Блокировка» event loop

```js
console.log("Start");
setTimeout(() => console.log("Timeout"), 0);

const start = Date.now();
while (Date.now() - start < 2000) {} // блокируем на 2 секунды

console.log("End");

// Вывод: Start → (пауза 2 сек) → End → Timeout
```

**Почему:** пока стек занят циклом while, event loop не может взять timeout-колбэк из очереди.

### fetch и Web APIs

```js
fetch('/api/data')
  .then(r => r.json())
  .then(data => console.log(data));

console.log("После fetch");
```

```
Стек: [fetch()] → [Promise.resolve()] → [console.log("После fetch")] → [пусто]
Web API: [HTTP-запрос] → ... → [Response готов]
Microtask queue: [then-колбэк] (когда Promise resolve'ится)

"После fetch" выводится сразу.
Когда HTTP-ответ придёт, then попадает в microtask queue и выполняется.
```

## Частые ошибки

**Ошибка 1: Думать, что setTimeout — точный**

```js
setTimeout(() => console.log("Done"), 100);
```

*Почему возникает:* «не раньше 100мс», а не «ровно через 100мс». Если стек занят, колбэк подождёт.

**Ошибка 2: Синхронный код в обработчике**

```js
button.addEventListener('click', () => {
  while (true) {} // страница зависнет!
});
```

*Почему возникает:* event loop не может прервать выполнение. Весь UI, включая рендеринг, остановится.

**Ошибка 3: Путать очереди**

```js
setTimeout(() => console.log("macrotask"), 0);
Promise.resolve().then(() => console.log("microtask"));
// microtask выведется раньше!
```
